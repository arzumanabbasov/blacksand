## Add an entry

1. Copy [TEMPLATE.md](TEMPLATE.md) into a new folder named YYYY-MM-DD-short-title, with the write-up saved as README.md.
2. Add reviewed screenshots, short clips and sanitized supporting files to that folder. Markdown can display images using relative paths; link larger recordings to their published location.
3. Fill in the actual target revision, agent/model setup, scope, outcome and verification. Leave unknown values explicit rather than guessing.
4. Add a newest-first row to the relevant table above, linking to the entry's README.md.
5. Link follow-up fixes, retests or disclosures when they become public. Date corrections instead of silently rewriting the result.

## What counts as evidence

Separate the agent's claims from independently reproduced results. Label entries as **agent-reported**, **human-reproduced**, or **externally-confirmed** and describe who checked what. For demos or benchmarks, explain the fixture and measurement method. A failed or inconclusive run is worth publishing when it teaches something.

Publish only work you are entitled to share. Keep nonpublic targets, credentials, session cookies and undisclosed vulnerabilities out of public entries. Store sanitized extracts here rather than uploading raw installation logs or databases. See [security guidance](../SECURITY.md).
